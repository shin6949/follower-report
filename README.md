# follower_report

X(트위터)와 YouTube의 팔로워·구독자 수를 조회해 SQLite에 쌓고, 오늘 기록을 표로 만들어 Discord 채널(또는 그 채널의 스레드)에 보내는 스크립트입니다.
여러 계정을 동시에 추적할 수 있고, X와 YouTube 중 한쪽만 써도 됩니다.

## 요구사항

- Python 3 (표준 라이브러리만 사용하므로 설치할 패키지가 없습니다. Python 3.9에서 확인했습니다.)
- 메시지를 받을 Discord 서버의 웹훅

## 설정

```
cp config.env.example config.env
```

`config.env`를 열어 값을 채웁니다. 한 줄에 `KEY=값` 형식이고, 따옴표는 없어도 됩니다.

| 키 | 필수 | 설명 |
|---|---|---|
| `DISCORD_WEBHOOK` | 예 | Discord 웹훅 URL. 채널 설정 > 연동 > 웹후크에서 복사합니다. |
| `DISCORD_THREAD_ID` | 아니오 | 보고를 올릴 스레드 ID. 웹훅을 만든 채널에 속한 스레드여야 합니다. 비워 두거나 줄을 지우면 웹훅의 채널에 바로 올립니다. |
| `X_USER` | 아니오 | 조회할 X 계정 이름(`@` 제외, 대소문자 구분). 콤마로 여러 개 입력합니다. |
| `YT_HANDLE` | 아니오 | 조회할 YouTube 채널 핸들(`@` 제외). 콤마로 여러 개 입력합니다. |

```
X_USER=KBSnews,Other_user
YT_HANDLE=newskbs
```

- `X_USER`와 `YT_HANDLE`은 둘 중 하나만 채워도 됩니다. 비어 있거나 줄이 없으면 그 플랫폼은 조회하지 않습니다. 둘 다 비면 실행되지 않습니다.
- `DISCORD_WEBHOOK`을 아는 사람은 누구나 해당 채널에 글을 쓸 수 있습니다. `config.env`는 `.gitignore`에 등록되어 있으니 커밋하지 마세요.

## 실행

```
python3 report.py
```

한 번 실행하면 모든 계정을 조회해 `followers.db`에 저장하고, 오늘 기록 전체를 Discord로 보냅니다. 같은 날 여러 번 실행하면 기록이 시간순으로 쌓입니다.

주기적으로 실행하는 방법은 아래 [주기 실행](#주기-실행)을 참고하세요.

## 주기 실행

`report.py`는 실행할 때마다 한 번 조회하고 끝나는 구조라서, 스케줄러가 주기적으로 실행해 주면 됩니다.
`config.env`와 `followers.db`는 스크립트가 있는 폴더를 기준으로 찾으므로 어느 폴더에서 실행해도 됩니다.
스케줄러에 등록하기 전에 `python3 report.py`를 직접 한 번 실행해서 메시지가 오는지 먼저 확인하세요.

### cron (Linux, macOS)

`crontab -e`로 편집기를 열고 한 줄을 추가합니다. 예: 매시 정각 실행

```
0 * * * * /usr/bin/python3 /path/to/follower_report/report.py >> ~/follower_report.log 2>&1
```

- 앞의 다섯 칸은 분·시·일·월·요일입니다. 30분마다 실행하려면 `*/30 * * * *`로 씁니다.
- cron은 PATH가 최소한만 잡혀 있으므로 `which python3`로 확인한 절대 경로를 씁니다.
- 로그에는 성공하면 `11:00 x:KBSnews=7828 youtube:newskbs=7070` 같은 한 줄이, 실패한 계정이 있으면 에러 내용이 함께 남습니다.

### 주의할 점

- **실행 간격**: 한 번의 실행이 끝나기 전에 다음 실행이 시작되지 않도록 간격은 수 분 이상으로 잡습니다. 틀린 X 계정이 있으면 계정마다 실행이 약 42초씩 길어집니다. 자주 실행할수록 하루 표가 길어져 메시지가 여러 개로 나뉩니다.
- **"오늘"의 기준**: 실행하는 컴퓨터의 로컬 날짜입니다. 서버 시간대가 UTC이면 한국 시간 오전 9시에 표가 새로 시작됩니다. 한국 시간 기준으로 하려면 시간대를 지정해서 실행합니다. 예: `0 * * * * TZ=Asia/Seoul /usr/bin/python3 /path/to/follower_report/report.py ...`
- **컴퓨터가 꺼져 있을 때**: 꺼져 있던 시간대는 기록이 빠져 표에 그 시각 줄이 없습니다. 상시 켜 두는 컴퓨터나 서버에서 돌리는 것을 권장합니다.
- **GitHub Actions**: `schedule`로 실행할 수는 있지만 실행마다 새 환경이라 `followers.db`가 남지 않아 하루 누적 표가 만들어지지 않습니다. DB를 따로 보존하는 구성이 필요하므로 권장하지 않습니다.

## 메시지 형식

```
증가량
[트위터 KBSnews / 트위터 Other_user / 유튜브 newskbs]
11:00 7,828/1,200/7,070
12:00 7,868(+40)/-/7,090(+20)
13:00 7,860(-8)/1,210(+10)/7,090(±0)
```

- 열 순서는 X 계정, YouTube 계정 순이고, 각 열은 설정 순서를 따릅니다.
- 괄호 안은 직전에 조회에 성공한 값과의 차이입니다. 조회에 실패한 시각은 `-`로 표시하고, 다음 성공값은 그 이전의 마지막 성공값과 비교합니다.
- Discord의 글자 수 제한 때문에 길어지면 여러 메시지로 나누어 보내며, 제목과 열 이름 줄은 메시지마다 반복합니다.

## 잘못된 계정 처리

- **형식이 잘못된 항목**(URL을 붙여넣었거나, 공백이 있거나, X 이름이 15자를 넘는 경우)은 조회하지 않고 건너뜁니다. 메시지 끝에 `⚠ 계정 이름 형식이 잘못되어 건너뜀: ...`으로 표시합니다.
- **형식은 맞지만 오늘 한 번도 조회되지 않은 계정**(철자 오류, 없는 계정 등)은 그 열이 `-`로 나오고, 메시지 끝에 `⚠ 오늘 조회된 값이 없음(계정 이름 확인): ...`으로 표시합니다.
- 한 계정이 실패해도 나머지 계정은 계속 조회합니다. 실패 이유는 표준 에러에 `fetch_x(계정) failed: ...` 형식으로 남습니다.

## 데이터

조회 결과는 스크립트와 같은 폴더의 `followers.db`(SQLite)에 쌓입니다.

```
follower_counts(checked_at TEXT, platform TEXT, account TEXT, count INTEGER)
```

한 행이 한 번의 조회 결과이고, 조회에 실패하면 `count`는 NULL입니다. `platform`은 `x` 또는 `youtube`입니다.
이전 버전이 만든 `snapshots` 테이블이 있으면 그대로 두며 읽지 않습니다.

```
sqlite3 followers.db "SELECT * FROM follower_counts ORDER BY checked_at DESC LIMIT 10"
```

## 테스트

```
python3 test_report.py
```

설정·표·메시지 분할 로직을 검사합니다. 네트워크에는 접속하지 않습니다.

## 한계

- X 수치는 비공식 서드파티 API(fxtwitter)로 가져옵니다. 이 API는 같은 계정에도 무작위로 404를 주는 일이 있어서 최대 15번 재시도하고, 없는 계정도 같은 404라 재시도를 끝까지 합니다. 잘못된 X 계정이 하나 있으면 실행마다 약 42초가 더 걸립니다.
- YouTube 수치는 채널 페이지 HTML에서 읽습니다. 화면에 줄여서 표시되는 값(예: 7.13K)을 환산하므로 정확한 숫자가 아니라 근삿값이며, 페이지 구조가 바뀌면 조회가 깨질 수 있습니다.
- 두 방식 모두 공식 API가 아니라서 서비스 약관상 허용 범위를 직접 확인하고 사용하세요. 막히면 공식 API로 바꾸는 것을 권합니다.
- 계정을 순서대로 하나씩 조회하므로 계정이 많을수록 실행 시간이 길어집니다.
